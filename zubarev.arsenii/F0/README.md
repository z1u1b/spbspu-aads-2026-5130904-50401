ФИО: Зубарев Арсений Юрьевич
Тема: "Файловая система в оперативной памят на основе сложной хеш-таблицы"
Описание:
Планируется создать версию файловой системы, хранящей данные в оперативной памяти. Структура директорий реализуется через хэш-таблицу с хэшированием Робин Гуда. Содержимое файлов сжимается алгоритмом Хаффмана на основе частоты символов перед размещением в памяти. Дедупликация данных реализуется через создание ссылок, то есть:
  1. каждый уникальный блок данных хранится в единственном экземпляре,
  2. а файлы с идентичным содержимым ссылаются на один блок через std::shared_ptr.
  3. Идентификация блоков осуществляется по хэшу данных до сжатия.
Планируются вот такие операции:
Создание/удаление директорий и вложенной структуры из них
Перемещение по вложенной структуре
Добавление файлов в директории
Изменение/удаление добавленных файлов
Сохранение/архивирование имеющейся файловой системы
В работе планируется использование умных указателей, чтобы корректно регулировать время жизни объектов без утечек памяти.

Дополнение:
Если останется время, то очень бы хотелось реализовать структуру LRU и кэширование. А также если еще время останется, то и нормальный поисковой движок. для них соответственно будут дополнительные команды

Список команд
mkdir <dir-name>
rm <path>
touch <file-name>
write <file-name> <file-text>
cat <file-name>
append <file-name> <file-new-text>
cd <path>
pwd
ls <path>
tree <path>
search <search-name>
save <dir-name>
load <file-name>
archive <dir-name>
home <dir-path>
mv <begin-path> <new-path>
cp <begin-path> <new-path>
...Описание команд

1. mkdir создаёт новую директорию в текущем рабочем каталоге. Команда некорректна, если директория с таким именем уже существует.
Для ввода:
mkdir docs
Ожидается вывод:
<OK>
Для ввода:
mkdir docs
Ожидается вывод:
<INVALID COMMAND>
...поскольку директория с именем docs уже существует.

2. rm удаляет файл или директорию по указанному пути. Система автоматически определяет тип объекта. Команда некорректна, если указанный путь не существует.
Для ввода:
rm notes.txt
Ожидается вывод:
<OK>
Для ввода:
rm unknown.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку файл или директория unknown.txt не найдены.

3. touch создаёт пустой файл в текущем каталоге. Если файл уже существует, команда выполняется без изменений и считается корректной.
Для ввода:
touch config.txt
Ожидается вывод:
<OK>
Для ввода:
touch config.txt
Ожидается вывод:
<OK>
...поскольку команда touch допустима даже при наличии файла.

4. write записывает указанный текст в файл, полностью заменяя его прежнее содержимое. Если файл не существует, он создаётся. Команда некорректна, если отсутствует аргумент <file-text>.
Для ввода:
write log.txt «Hello World»
Ожидается вывод:
<OK>
Для ввода:
write log.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку отсутствует обязательный аргумент <file-text>.

5. cat выводит содержимое указанного файла. Команда некорректна, если файл не существует.
Для ввода:
cat log.txt
Ожидается вывод:
Hello World
Для ввода:
cat missing.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку файл missing.txt не найден.

6. append добавляет указанный текст в конец существующего файла. Команда некорректна, если файл не существует или отсутствует текст для добавления.
Для ввода:
append log.txt «New line»
Ожидается вывод:
<OK>
Для ввода:
append missing.txt «New line»
Ожидается вывод:
<INVALID COMMAND>
...поскольку файл missing.txt не существует.

7. cd изменяет текущую рабочую директорию на указанную. Команда некорректна, если путь не существует или указывает на файл вместо директории.
Для ввода:
cd docs
Ожидается вывод:
<OK>
Для ввода:
cd notes.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку notes.txt является файлом, а не директорией.

8. pwd выводит абсолютный путь текущей рабочей директории. Команда всегда корректна.
Для ввода:
pwd
Ожидается вывод:
/home/user/docs
...поскольку команда pwd не требует аргументов и всегда возвращает текущий путь.

9. ls выводит список файлов и поддиректорий в указанной директории. Если путь не указан, выводит содержимое текущей директории. Команда некорректна, если путь существует, но является файлом.
Для ввода:
ls docs
Ожидается вывод:
file1.txt file2.txt subfolder/
Для ввода:
ls docs/file1.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку команда ls ожидает директорию, а не файл.

10. tree выводит древовидную структуру вложенности файлов и директорий, начиная с указанного пути. Если путь не указан, строит дерево от текущей директории. Команда некорректна, если путь не существует.
Для ввода:
tree project
Ожидается вывод:
project/
-src/
—main.txt
Для ввода:
tree missing_dir
Ожидается вывод:
<INVALID COMMAND>
...поскольку директория missing_dir не найдена.
11. search ищет файлы и директории по точному имени во всей доступной файловой системе. Команда всегда корректна, возвращает список найденных путей или сообщение об отсутствии.
Для ввода:
search main.txt
Ожидается вывод:
/home/docs/main.txt /home/project/src/main.txt
Для ввода:
search nonexistent.xyz
Ожидается вывод:
<NOT FOUND>
...поскольку объектов с именем nonexistent.xyz не обнаружено.

12. save сохраняет указанную директорию и всё её содержимое в постоянном хранилище сессии. Данные не копируются физически: фиксируются только метаданные структуры (время создания  и еще что-то можно придумать)  и ссылки на уникальные блоки. Команда некорректна, если директория не существует, не является директорией или объект с таким именем уже зарегистрирован в хранилище.

Для ввода:
save backup
Ожидается вывод:
<SAVED>
Для ввода:
save backup
Ожидается вывод:
<INVALID COMMAND>
...поскольку директория backup уже находится в постоянном хранилище.


13. load восстанавливает указанный файл из постоянного хранилища сессии в текущую рабочую директорию. Создаётся новый узел File, который получает ссылку на существующий блок данных (дублирование в памяти не происходит). Команда некорректна, если файл отсутствует в реестре, уже существует в текущем каталоге или указанное имя относится к директории.

Для ввода:
load config.txt
Ожидается вывод:
<LOADED>
Для ввода:
load missing.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку файл missing.txt не найден в постоянном хранилище.

Для ввода:
load config.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку файл config.txt уже существует в текущем каталоге (перезапись запрещена).

14. archive создаёт сжатый архив указанной директории в текущем каталоге. Все файлы рекурсивно упаковываются в единый бинарный контейнер с применением алгоритма Хаффмана. Команда некорректна, если директория не существует или файл архива с таким именем уже занят.

Для ввода:
archive docs
Ожидается вывод:
<ARCHIVED: docs.zip>
Для ввода:
archive missing
Ожидается вывод:
<INVALID COMMAND>
...поскольку директория missing не найдена.

15. states выводит список доступных файлов состояний (сессий), найденных в директории привязки или указанном пути. Команда всегда корректна, возвращает список имён файлов с метаданными (размер, дата изменения) или сообщение, если список пуст.

Для ввода:
states
Ожидается вывод:
coursework_v1.state [12KB, 2025-01-15]
coursework_final.state [45KB, 2025-01-20]
Для ввода:
states /empty_folder
Ожидается вывод:
<NO STATES FOUND>
...поскольку в указанной директории отсутствуют файлы состояний.

16. import копирует файл из реальной файловой системы (диска) в текущую директорию виртуальной ФС. Содержимое файла считывается, сжимается алгоритмом Хаффмана и регистрируется в хранилище блоков. Команда некорректна, если исходный файл не существует на диске, не является файлом или целевое имя уже занято в текущем каталоге.

Для ввода:
import /home/user/data.txt report.txt
Ожидается вывод:
<IMPORTED: /home/user/data.txt -> report.txt>
Для ввода:
import /home/user/missing.txt report.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку файл /home/user/missing.txt не найден в реальной файловой системе.

Для ввода:
import /home/user/data.txt report.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку файл report.txt уже существует в текущем каталоге.

17. export копирует файл из текущей директории виртуальной ФС в реальную файловую систему (на диск). Содержимое файла распаковывается (декод Хаффмана) и записывается в указанный путь. Команда некорректна, если исходный файл не существует в виртуальной ФС, является директорией или целевой путь недоступен для записи.

Для ввода:
export report.txt /home/user/submission/report.txt
Ожидается вывод:
<EXPORTED: report.txt -> /home/user/submission/report.txt>
Для ввода:
export missing.txt /home/user/report.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку файл missing.txt не найден в виртуальной файловой системе.

Для ввода:
export report.txt /root/protected/report.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку путь /root/protected/ недоступен для записи (отказано в доступе).

18. start-state загружает сохранённую сессию из указанного файла состояния, полностью заменяя текущую файловую систему на восстановленную. Все данные, структура директорий и внутренний реестр восстанавливаются из сериализованного снимка. Команда некорректна, если файл состояния не существует, повреждён или текущая файловая система не пуста (требуется подтверждение перезаписи).

Для ввода:
start-state coursework_v1.state
Ожидается вывод:
<STATE LOADED: coursework_v1.state>
Для ввода:
start-state missing.state
Ожидается вывод:
<INVALID COMMAND>
...поскольку файл состояния missing.state не найден или повреждён.

Для ввода:
start-state coursework_v1.state
Ожидается вывод:
<INVALID COMMAND>
...поскольку текущая файловая система не пуста (используйте start-state <file> true для принудительной загрузки).

20. cashe_size выделяет указанное количество памяти в оперативной памяти для кэширования файлов и директорий. Если не указана, используется фиксированное значение по умолчанию. Команда некорректна, если указан отрицательный размер или нечисловое значение. По умолчанию (если не введен размер) будут устанавливаться МВ.
Для ввода:
cashe_size 512MB
Ожидается вывод:
<CACHE SIZE SET: 512MB>
Для ввода:
cashe_size -100
Ожидается вывод:
<INVALID COMMAND>
...поскольку размер кэша не может быть отрицательным.

21. cache_on включает систему кэширования: часто используемые файлы и директории автоматически сохраняются в выделенной области памяти для ускорения доступа. Команда некорректна, если кэширование уже включено.
Для ввода:
cache on
Ожидается вывод:
<CACHE ENABLED>
Для ввода:
cache on
Ожидается вывод:
<INVALID COMMAND>
...поскольку кэширование уже активно.

22. cache_off отключает систему кэширования: все данные из кэша сбрасываются, последующие операции чтения/записи выполняются напрямую. Команда некорректна, если кэширование уже отключено.
Для ввода:
cache off
Ожидается вывод:
<CACHE DISABLED>
Для ввода:
cache off
Ожидается вывод:
<INVALID COMMAND>
...поскольку кэширование уже отключено.

23. cache_stats выводит статистику использования кэша: список закэшированных объектов, их размер, приоритет и время последнего доступа (пока еще не решил, как приоритетность буду определять и сколько приоритетов будет). Команда некорректна, если кэширование отключено.
Для ввода:
cache stats
Ожидается вывод:
CACHED: 3 items
- docs/ [256KB, priority: HIGH, last: 2m ago]
- config.txt [4KB, priority: MEDIUM, last: 5m ago]
- log.txt [12KB, priority: LOW, last: 15m ago]
Для ввода:
cache stats
Ожидается вывод:
<INVALID COMMAND>
...поскольку кэширование отключено и статистика недоступна.

24. ssearch выполняет умный поиск файлов и директорий по заданному критерию: name (по имени), content (по содержимому) или ext (по расширению). Команда некорректна, если указан неподдерживаемый тип поиска, отсутствует текст для поиска или нарушен формат аргументов.
Для ввода:
ssearch name report.txt
Ожидается вывод:
/docs/report.txt
/archive/old_report.txt
Для ввода:
ssearch unknown_type hello
Ожидается вывод:
<INVALID COMMAND>
...поскольку тип поиска unknown_type не поддерживается (допустимы только: name, content, `ext`).
