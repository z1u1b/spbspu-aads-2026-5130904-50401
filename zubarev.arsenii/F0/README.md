ФИО: Зубарев Арсений Юрьевич
Тема: "Файловая система в оперативной памяти на основе сложной хеш-таблицы"
Описание:
Планируется создать версию файловой системы, хранящей данные в оперативной памяти. Структура директорий реализуется через хэш-таблицу с хэшированием Робин Гуда. Содержимое файлов сжимается алгоритмом Хаффмана на основе частоты символов перед размещением в памяти. Дедупликация данных реализуется через создание ссылок, то есть:
  1. каждый уникальный блок данных хранится в единственном экземпляре,
  2. а файлы с идентичным содержимым ссылаются на один блок через std::shared_ptr.
  3. Идентификация блоков осуществляется по двойному хэшу данных до сжатия (SipHash + XXHash).
Планируются вот такие операции:
Создание/удаление директорий и вложенной структуры из них
Перемещение по вложенной структуре
Добавление файлов в директории
Изменение/удаление добавленных файлов
Сохранение/архивирование имеющейся файловой системы
В работе планируется использование умных указателей, чтобы корректно регулировать время жизни объектов без утечек памяти.

Дополнение:
Если останется время, то очень бы хотелось реализовать структуру LRU и кэширование. А также если еще время останется, то и нормальный поисковой движок. для них соответственно будут дополнительные команды

...Описание команд

1. mkdir создаёт новую директорию в текущем рабочем каталоге. Команда некорректна, если директория с таким именем уже существует или имя содержит недопустимые символы.
Для ввода:
mkdir docs
Ожидается вывод:
<OK>
Для ввода:
mkdir docs
Ожидается вывод:
mkdir: docs: File exists
...поскольку директория с именем docs уже существует.

2. rmdir удаляет пустую директорию по указанному имени. Команда некорректна, если директория не существует, не является директорией или не пуста.
Для ввода:
rmdir docs
Ожидается вывод:
<OK>
Для ввода:
rmdir docs
Ожидается вывод:
rmdir: docs: Directory not empty
...поскольку директория docs не пуста.

3. rm удаляет файл по указанному имени. Команда некорректна, если файл не существует или является директорией.
Для ввода:
rm notes.txt
Ожидается вывод:
<OK>
Для ввода:
rm unknown.txt
Ожидается вывод:
rm: unknown.txt: No such file or directory
...поскольку файл unknown.txt не найден.

4. touch создаёт пустой файл в текущем каталоге. Команда некорректна, если файл уже существует или имя содержит недопустимые символы.
Для ввода:
touch config.txt
Ожидается вывод:
<OK>
Для ввода:
touch config.txt
Ожидается вывод:
touch: config.txt: File exists
...поскольку файл config.txt уже существует.

5. write записывает указанный текст в файл, полностью заменяя его прежнее содержимое. Текст разбивается на блоки по 4096 байт, каждый блок сжимается алгоритмом Хаффмана и регистрируется в глобальном реестре. Команда некорректна, если файл не существует (должен быть создан через touch).
Для ввода:
write log.txt "Hello World"
Ожидается вывод:
<OK>
Для ввода:
write log.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку отсутствует обязательный аргумент <file-text>.

6. cat выводит содержимое указанного файла, автоматически распаковывая все блоки алгоритмом Хаффмана. Команда некорректна, если файл не существует или является директорией.
Для ввода:
cat log.txt
Ожидается вывод:
Hello World
Для ввода:
cat missing.txt
Ожидается вывод:
cat: missing.txt: No such file or directory
...поскольку файл missing.txt не найден.

7. append добавляет указанный текст в конец существующего файла, создавая новые блоки данных. Команда некорректна, если файл не существует или отсутствует текст для добавления.
Для ввода:
append log.txt "New line"
Ожидается вывод:
<OK>
Для ввода:
append missing.txt "New line"
Ожидается вывод:
append: missing.txt: No such file
...поскольку файл missing.txt не существует.

8. cd изменяет текущую рабочую директорию на указанную. Поддерживаются относительные пути, абсолютные пути (от корня ~), а также специальные обозначения . и ... Команда некорректна, если путь не существует или указывает на файл вместо директории.
Для ввода:
cd docs
Ожидается вывод:
<OK>
Для ввода:
cd notes.txt
Ожидается вывод:
cd: notes.txt: No such directory
...поскольку notes.txt является файлом, а не директорией.

9. pwd выводит абсолютный путь текущей рабочей директории в формате ~/path/to/dir. Команда всегда корректна.
Для ввода:
pwd
Ожидается вывод:
~/docs
...поскольку команда pwd не требует аргументов и всегда возвращает текущий путь.

10. ls выводит список файлов и поддиректорий в указанной директории. Если путь не указан, выводит содержимое текущей директории.
Для ввода:
ls docs
Ожидается вывод:
file1.txt file2.txt subfolder
Для ввода:
ls missing_dir
Ожидается вывод:
<OK>
...вывод будет пустым, поскольку директория не найдена.

11. tree выводит древовидную структуру вложенности файлов и директорий, начиная с указанного пути, используя псевдографику. Если путь не указан, строит дерево от текущей директории. Также выводит количество директорий и файлов.
Для ввода:
tree project
Ожидается вывод:
.
├── src
│   └── main.txt
└── docs
2 directories, 1 files
Для ввода:
tree missing_dir
Ожидается вывод:
<INVALID COMMAND>
...поскольку директория missing_dir не найдена.

12. search ищет файлы и директории по точному имени во всей доступной файловой системе. Команда всегда корректна, возвращает список найденных путей или пустой результат.
Для ввода:
search main.txt
Ожидается вывод:
~/docs/main.txt ~/project/src/main.txt
Для ввода:
search nonexistent.xyz
Ожидается вывод:
<NOT FOUND>
...поскольку объектов с именем nonexistent.xyz не обнаружено.

13. save сохраняет указанную директорию и всё её содержимое в постоянном хранилище сессии в оперативной памяти. Данные не копируются физически: фиксируются только метаданные структуры и ссылки на уникальные блоки. Команда некорректна, если директория не существует или объект с таким именем уже зарегистрирован в хранилище.
Для ввода:
save backup
Ожидается вывод:
<SAVED>
Для ввода:
save backup
Ожидается вывод:
<INVALID COMMAND>
...поскольку директория backup уже находится в постоянном хранилище.

14. load восстанавливает указанный объект из постоянного хранилища сессии в текущую рабочую директорию. Создаётся новый узел, который получает ссылку на существующие блоки данных (дублирование в памяти не происходит). Команда некорректна, если объект отсутствует в реестре или уже существует в текущем каталоге.
Для ввода:
load config.txt
Ожидается вывод:
<LOADED>
Для ввода:
load missing.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку объект missing.txt не найден в постоянном хранилище.

15. archive создаёт сжатый архив указанной директории в текущем каталоге. Все файлы рекурсивно упаковываются в единый бинарный контейнер с применением алгоритма Хаффмана. Команда некорректна, если директория не существует или файл архива с таким именем уже занят.
Для ввода:
archive docs
Ожидается вывод:
<ARCHIVED: docs.zip>
Для ввода:
archive missing
Ожидается вывод:
<INVALID COMMAND>
...поскольку директория missing не найдена.

16. states выводит список доступных файлов состояний (сессий), найденных в директории привязки или указанном пути. Команда всегда корректна, возвращает список имён файлов с метаданными (размер, дата изменения) или сообщение, если список пуст.
Для ввода:
states
Ожидается вывод:
coursework_v1.state [12KB, 2025-01-15]
coursework_final.state [45KB, 2025-01-20]
Для ввода:
states /empty_folder
Ожидается вывод:
<NO STATES FOUND>
...поскольку в указанной директории отсутствуют файлы состояний.

17. import копирует файл из реальной файловой системы (диска) в текущую директорию виртуальной ФС. Содержимое файла считывается, сжимается алгоритмом Хаффмана и регистрируется в хранилище блоков. Команда некорректна, если исходный файл не существует на диске или целевое имя уже занято.
Для ввода:
import /home/user/data.txt report.txt
Ожидается вывод:
<IMPORTED: /home/user/data.txt -> report.txt>
Для ввода:
import /home/user/missing.txt report.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку файл /home/user/missing.txt не найден в реальной файловой системе.

18. export копирует файл из текущей директории виртуальной ФС в реальную файловую систему (на диск). Содержимое файла распаковывается (декод Хаффмана) и записывается в указанный путь. Команда некорректна, если исходный файл не существует в виртуальной ФС или целевой путь недоступен для записи.
Для ввода:
export report.txt /home/user/submission/report.txt
Ожидается вывод:
<EXPORTED: report.txt -> /home/user/submission/report.txt>
Для ввода:
export missing.txt /home/user/report.txt
Ожидается вывод:
<INVALID COMMAND>
...поскольку файл missing.txt не найден в виртуальной файловой системе.

19. start-state загружает сохранённую сессию из указанного файла состояния, полностью заменяя текущую файловую систему на восстановленную. Все данные, структура директорий и внутренний реестр восстанавливаются из сериализованного снимка. Если текущая файловая система не пуста, выводится интерактивное меню с выбором: сохранить текущее состояние в новый файл, отменить загрузку или продолжить с затиранием текущих данных. Команда некорректна, если файл состояния не существует или повреждён.
Для ввода:
start-state coursework_v1.state
Ожидается вывод:
<STATE START COMPLETE>
Для ввода:
start-state missing.state
Ожидается вывод:
start-state: missing.state [error opening file]
...поскольку файл состояния missing.state не найден.

Для ввода:
start-state coursework_v1.state
Ожидается вывод:
WARNING: Current file system is not empty.
Loading a new state will affect your current files.
Choose an option:
  1. Save current state to a new file, then load
  2. Discard current state and load new
  3. Cancel loading
Enter choice (1/2/3):
...поскольку текущая файловая система не пуста и требуется подтверждение пользователя.

20. save-state сохраняет текущую сессию (файловую систему из оперативной памяти) в указанный файл состояния на реальном диске. Она полностью сериализует текущую структуру директорий и содержимое файлов. Файл должен иметь расширение .state. Команда некорректна, если файл на диске уже существует (требуется флаг true для перезаписи), если текущая файловая система пуста или если расширение файла некорректно.
Для ввода:
save-state coursework_v1.state
Ожидается вывод:
<STATE SAVED COMPLETE>
Для ввода:
save-state coursework_v1.state
Ожидается вывод:
save-state: coursework_v1.state already exists. Use force=true to overwrite.
...поскольку файл состояния coursework_v1.state уже существует на диске.

Для ввода:
save-state coursework_v1.state true
Ожидается вывод:
<STATE SAVED COMPLETE>
...поскольку указан флаг перезаписи.

Для ввода:
save-state coursework_v1
Ожидается вывод:
save-state: coursework_v1 invalid extension
...поскольку файл не имеет расширения .state.

21. cache_size выделяет указанное количество памяти в оперативной памяти для кэширования файлов и директорий. Если не указана, используется фиксированное значение по умолчанию. Команда некорректна, если указан отрицательный размер или нечисловое значение. По умолчанию (если не введен размер) будут устанавливаться МВ.
Для ввода:
cache_size 512MB
Ожидается вывод:
<CACHE SIZE SET: 512MB>
Для ввода:
cache_size -100
Ожидается вывод:
<INVALID COMMAND>
...поскольку размер кэша не может быть отрицательным.

22. cache_on включает систему кэширования: часто используемые файлы и директории автоматически сохраняются в выделенной области памяти для ускорения доступа. Команда некорректна, если кэширование уже включено.
Для ввода:
cache_on
Ожидается вывод:
<CACHE ENABLED>
Для ввода:
cache_on
Ожидается вывод:
<INVALID COMMAND>
...поскольку кэширование уже активно.

23. cache_off отключает систему кэширования: все данные из кэша сбрасываются, последующие операции чтения/записи выполняются напрямую. Команда некорректна, если кэширование уже отключено.
Для ввода:
cache_off
Ожидается вывод:
<CACHE DISABLED>
Для ввода:
cache_off
Ожидается вывод:
<INVALID COMMAND>
...поскольку кэширование уже отключено.

24. cache_stats выводит статистику использования кэша: список закэшированных объектов, их размер, приоритет и время последнего доступа. Команда некорректна, если кэширование отключено.
Для ввода:
cache_stats
Ожидается вывод:
CACHED: 3 items
- docs/ [256KB, priority: HIGH, last: 2m ago]
- config.txt [4KB, priority: MEDIUM, last: 5m ago]
- log.txt [12KB, priority: LOW, last: 15m ago]
Для ввода:
cache_stats
Ожидается вывод:
<INVALID COMMAND>
...поскольку кэширование отключено и статистика недоступна.

25. ssearch выполняет умный поиск файлов и директорий по заданному критерию: name (по имени), content (по содержимому) или ext (по расширению). Команда некорректна, если указан неподдерживаемый тип поиска, отсутствует текст для поиска или нарушен формат аргументов.
Для ввода:
ssearch name report.txt
Ожидается вывод:
/docs/report.txt
/archive/old_report.txt
Для ввода:
ssearch unknown_type hello
Ожидается вывод:
<INVALID COMMAND>
...поскольку тип поиска unknown_type не поддерживается (допустимы только: name, content, ext).
